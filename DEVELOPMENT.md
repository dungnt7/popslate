# Developing Popslate

How to build, test and release Popslate, and how it works inside. For what the app does and how to use it, see the [README](README.md).

## Tech Stack

| Part | Choice |
|---|---|
| App framework | [Tauri 2](https://tauri.app): Rust backend, the system WebView2 for the UI |
| UI | Plain HTML, CSS and JavaScript in `ui/`. No framework, no bundler, no build step |
| HTTP | `reqwest` with rustls and HTTP/2 |
| Windows APIs | `windows` crate: UI Automation, `SendInput`, clipboard |
| Tauri plugins | `global-shortcut`, `single-instance`, `autostart` |
| Installer | NSIS, generated by `tauri build` |

## Set Up a Development Environment

Install once:

1. **Rust** (stable) via [rustup](https://rustup.rs).
2. **Visual Studio Build Tools** with the **Desktop development with C++** workload. Rust needs its linker on Windows.
3. **Node.js** 18 or newer. It is only here for the Tauri CLI.
4. **WebView2 runtime.** Built into Windows 11. On Windows 10, install it from Microsoft if it is missing.

With `winget`:

```powershell
winget install Rustlang.Rustup
winget install Microsoft.VisualStudio.BuildTools --override "--quiet --wait --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
winget install OpenJS.NodeJS.LTS
```

The Build Tools take several gigabytes of disk space; Rust uses them mainly to link. Open a new terminal afterwards so `cargo` is on the PATH (in VS Code, restart the whole editor). Then:

```powershell
git clone https://github.com/dungnt7/popslate.git
cd popslate
npm install
npm run dev
```

## Commands

| Command | What it does |
|---|---|
| `npm run dev` | Build and run a debug build. Logs go to the console |
| `npm run build` | Release build plus installer in `src-tauri/target/release/bundle/nsis/` |
| `npm run icons` | Regenerate every icon from the SVG sources |
| `cargo test` (in `src-tauri`) | Unit tests, offline |
| `cargo test -- --ignored` (in `src-tauri`) | Live test against Google Translate |
| `cargo clippy --all-targets -- -W clippy::undocumented_unsafe_blocks` (in `src-tauri`) | Lints, including a `// SAFETY:` comment on every `unsafe` block |
| `powershell -ExecutionPolicy Bypass -File scripts/e2e-selection.ps1` | End-to-end test (see [End-to-End Test](#end-to-end-test)) |

## Project Layout

```
src-tauri/src/
  main.rs        app setup: tray, hotkey, windows, the hotkey worker thread
  selection.rs   read the selected text in another app (Windows only)
  translate.rs   Google Translate client
  popup.rs       popup placement, sizing, show and hide
  config.rs      settings: load, save, apply (hotkey, autostart)
ui/
  popup.html     the translation popup
  settings.html  the settings window
src-tauri/icons/icon.svg, icon-16.svg   icon sources
src-tauri/installer-hooks.nsh           NSIS uninstall hook
scripts/e2e-selection.ps1               end-to-end test
docs/                                   README screenshots
```

## How a Translation Happens

1. The global shortcut fires. One worker thread handles every press, so two captures never overlap.
2. `selection.rs` asks the focused app for its selection through **UI Automation**. This leaves the clipboard alone.
3. If that gives nothing, it falls back to **Ctrl+C**: wait until the user lets go of the shortcut's modifier keys, take a snapshot of the clipboard, send Ctrl+C, poll `GetClipboardSequenceNumber` until the clipboard changes (300 ms limit), read the text, restore the snapshot.
4. The text is cleaned (line endings, trailing spaces, runs of blank lines) and sent to Google.
5. Rust emits a `popup` event. The page renders, measures its content and calls `popup_fit`. Rust then sizes, places and shows the window. Results from older presses are dropped.

## Important Notes

- **Translation endpoint.** `translate.google.com/translate_a/single?client=gtx` is the free, unofficial endpoint that browser extensions use. It is free and has no contract; those two facts come as a pair. It answers in about 45 ms, while `translate.googleapis.com` (same JSON, same model) took about 430 ms when measured. One POST handles about 60,000 characters, so there is no chunking. The connection opens at startup and stays open.
- **Ctrl+C fallback.** Ctrl+C sent while the user still holds Alt arrives as Ctrl+Alt+C, which copies nothing. That is why the code waits for the modifiers to be released. An unassigned key (`0xE8`) is tapped right after the hotkey, so letting go of Alt does not open the menu bar of the app underneath. Ctrl+C is never sent to Windows Terminal or console windows.
- **No UI Automation.** If UI Automation cannot be created, `Selector` keeps working with the Ctrl+C fallback only. A missing COM component should not take the hotkey down with it.
- **Popup focus.** tao reports `Focused(false)` whenever focus moves inside the popup (into the webview, or while dragging the header). The popup only hides after checking that another window really became the foreground window (`popup::hide_if_inactive`).
- **Memory.** About 100 MB of private memory at idle. The Rust process uses about 8 MB; the browser engine that draws one small popup uses the rest. Two measures keep it there: the settings window is built when opened and destroyed when closed, and WebView2 runs with `--disable-gpu`, which costs nothing measurable for a text popup. The popup window is built once at startup and reused, for speed.
- **Windows are built in code.** Both windows are `"create": false` in `tauri.conf.json` and are built by `build_window` in `main.rs`, so they share one WebView2 data folder.
- **Data folders.** Settings: `%APPDATA%\.popslate\config.json`. WebView2 data: `%LOCALAPPDATA%\.popslate\`. The folder name is set in `config.rs` and must match `installer-hooks.nsh`. A `config.json` that is not valid JSON is renamed to `config.json.bad` and defaults are used, so a typo in a hand edit is never silently overwritten.
- **Logs.** Release builds log timings, languages and text length, never the text itself. Debug builds also log the selected text and the translation.
- **Autostart in dev builds.** Debug builds never write the "start with Windows" registry entry, so a dev build does not launch at sign-in.
- **Version.** Set only in `src-tauri/Cargo.toml`; `tauri.conf.json` reads it from there.
- **Icons.** Edit `src-tauri/icons/icon.svg` (app icon, and the 20 to 32 px tray icons) or `icon-16.svg` (the pixel-drawn 16 px tray icon), then run `npm run icons`. The output is the same byte for byte on every run. The tray picks the size that matches the display scaling at startup.
- **Platform.** Windows only for now. `selection.rs`, `popup::hide_if_inactive` and `open_homepage` are the Windows-specific parts; macOS and Linux need their own versions of them.

## End-to-End Test

`scripts/e2e-selection.ps1` opens small test windows, selects text, presses <kbd>Alt</kbd>+<kbd>Q</kbd> and checks each selection path: UI Automation, Ctrl+C from an edit box, Ctrl+C from a window without text support, and nothing selected. It also checks that the clipboard comes back unchanged. Don't use the keyboard or mouse while it runs; it is borrowing them.

Set `POPSLATE_EXE` to test another build, for example the installed one:

```powershell
$env:POPSLATE_EXE = "$env:LOCALAPPDATA\Popslate\popslate.exe"
powershell -ExecutionPolicy Bypass -File scripts/e2e-selection.ps1
```

## Release

1. Bump `version` in `src-tauri/Cargo.toml`.
2. Run `npm run build`.
3. Upload `src-tauri/target/release/bundle/nsis/Popslate_<version>_x64-setup.exe` to a new GitHub release.
